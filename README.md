# 에너지 인사이트 — 작업 중

공장과 건물의 전기·가스·수도 데이터를 살펴보기 위한 에너지 관리 시스템입니다. 현재는 개발 초기 단계이며 실제 기업 운영에 사용할 수 없습니다.

## 로컬 실행

Node.js 20 이상을 준비한 뒤 프로젝트 루트에서 다음을 실행합니다.

```sh
npm install
npm run dev
```

터미널에 표시된 주소(보통 http://localhost:3000)를 브라우저에서 여세요. Windows PowerShell에서 npm.ps1 실행 정책 오류가 발생하면 `npm.cmd install`과 `npm.cmd run dev`를 대신 사용할 수 있습니다.

관리자 로그인 설정은 Git에 포함되지 않는 `.env.local`에 저장됩니다. 비밀번호 변경은 로그인 후 오른쪽 위 마이페이지에서 현재 비밀번호를 확인한 뒤 할 수 있습니다. 변경된 비밀번호의 해시는 Git에 포함되지 않는 `.data/account.json`에 저장되며 기존 세션은 만료됩니다. 해당 로컬 파일을 삭제하면 초기 설정으로 돌아가므로 보존에 주의하세요. 데모용 단일 서버 계정이며, 운영용 SSO·복구 절차·다중 서버 세션을 대체하지 않습니다.

## 현재 범위

- 사업장·기간 선택, 대시보드, 사용량 요약, 이상 사례 상세, 절감 조치와 관측 결과 목록을 시연합니다.
- 이상·조치 메뉴의 데모 업무 처리에서 역할 선택, 사업장 제한 조회, 이상 상태 변경과 조치 등록·상태 변경을 할 수 있으며 결과가 대시보드에 반영됩니다. 변경 이력과 조치·검증 결과는 로컬 `.data/demo.json`에 저장되므로 단일 프로세스 시연용입니다.
- `DATABASE_URL`이 없으면 시뮬레이션 사용량을 읽습니다. 설정하면 PostgreSQL의 최근 400일 일별 데이터만 읽으며 DB 오류 시 임의로 시뮬레이션으로 대체하지 않습니다. PostgreSQL 실행 후 `.env`에 연결 주소를 설정하고 `npm run db:migrate`, `npm run db:seed`를 실행하세요. Docker Compose에는 `POSTGRES_USER`, `POSTGRES_PASSWORD`가 필요합니다.
- DB 사용 시 기본 출처는 `csv-import`입니다. 계량기·데이터 품질 메뉴에서 평택 제1공장의 일별 전기 CSV를 미리 보고 가져올 수 있습니다. UTF-8 파일의 헤더는 `date,value`, 날짜는 `YYYY-MM-DD`, 단위는 `kWh`입니다. 예: `2026-01-01,123.5`. 중복 날짜는 덮어쓰지 않습니다. 현재는 지정된 평택 일별 전기 계량기만 지원합니다.
- 가져오기마다 CSV 텍스트의 SHA-256 해시, 계정, 시각 및 처리 건수를 DB에 저장하고 새 계량값과 연결합니다. 원본 파일, 실패한 시도 및 기존 데이터의 이력은 저장하지 않습니다. 이 기록은 검증 승인이나 불변 감사 로그를 대체하지 않습니다. 기존 DB에는 마이그레이션을 적용하세요.
- CSV 보고서의 완전성 표는 선택 기간의 달력 일수와 수신 날짜를 비교합니다. 계량기 설치 여부나 수집 주기를 반영하지 않으므로 미수신 일수가 반드시 실제 결측을 뜻하지 않습니다.
- 시드 데이터를 DB에서 살펴보려면 `EMS_READING_SOURCE=demo-seed`로 설정한 뒤 서버를 재시작합니다. 시뮬레이션과 업로드 값은 별도 계량기와 출처로 분리하며 합산하지 않습니다. 다시 업로드 자료를 보려면 값을 지우거나 `csv-import`로 바꾸세요.
- DB의 일별 전기 데이터에서 가장 최근 날짜가 이전 동일 요일 7개 이상 중앙값보다 30% 초과한 경우 이상 의심 항목을 표시합니다. 기온·생산량 보정과 야간 전용 판단은 수행하지 않습니다.
- 평택 일별 전력 비교는 기준·사후 기간이 겹치지 않고 같은 길이의 7일 배수이며 하루도 누락·중복되지 않아야 합니다. 보정이 없는 단순 사용량 차이로, 실제 검증 완료 절감 성과가 아닙니다. 별도 수동 계산도 제공합니다.
- 리포트 센터에서 상단 필터가 적용된 CSV 사용 현황을 내려받을 수 있습니다. 단가와 탄소 계수는 데모 수치이며 실제 청구서·공식 보고용이 아닙니다.
- `src/features`에 업무 기능별 모델과 화면을 나누고, 공통 표시 함수는 `src/shared`에 둡니다.
- 데이터는 실행 시 생성되는 가상 수치입니다. 비용은 데모 단가를, 탄소는 임의의 데모 배출계수를 사용하며 공식 보고에 사용하면 안 됩니다. 수도 탄소배출은 포함하지 않습니다.

## 아직 구현되지 않은 사항

계량기 자동 연동·데이터 정정, 실제 인증과 기업 수준 사업장별 권한, 불변 감사 로그, 조치 승인, 시간대별·기온·생산량 보정 성과 검증, PDF/XLSX 보고서 및 운영 보안 등은 아직 구현되지 않았습니다. 업무 데이터는 PostgreSQL이 아니라 로컬 JSON에 저장됩니다. DB 조회와 가져오기는 평택 일별 전기 및 시드된 식별자에 한정된 초기 구현이며 다른 사업장의 실제 계량기를 임의로 연결하지 않습니다. DB 없는 모드의 이상 사례는 사전 작성된 데모입니다.

데모 역할은 누구나 변경할 수 있으므로 인증 시스템이 아닙니다. 프로덕션 모드에서는 데모 역할 API가 기본 비활성화됩니다. 환경 변수로 이를 켜더라도 실제 운영 인증을 대신할 수 없습니다. 서버 프로세스를 재시작하면 데모 세션이 만료됩니다.

`npm run lint`, `npm run typecheck`, `npm test`, `npm run test:e2e`로 점검할 수 있습니다. E2E 실행에는 Playwright 브라우저 설치가 필요합니다. 2026-11-25 기준 npm 감사에서 운영 의존성 취약점이 보고되어 해결 전에는 배포하지 마세요.
